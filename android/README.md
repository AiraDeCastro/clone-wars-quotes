# Android Scaffold

This is a source-level scaffold for the Android app + Jetpack Glance widget, written and reviewed on a Windows machine with no JDK, Android SDK, or Gradle available. **Nothing in here has been compiled, synced, or run yet.** Treat it as a strong starting point, not a verified build — that verification is the first thing to do once you're on a machine with the Android toolchain.

## What's here

- `settings.gradle.kts`, `build.gradle.kts`, `gradle/libs.versions.toml` — a two-module Gradle project using a version catalog. Versions pinned (Kotlin 2.0.21, AGP 8.7.2, Glance 1.1.1, Compose BOM 2024.12.01) are plausible current-ish versions, **not verified to resolve** — Android Studio will likely prompt an AGP/Gradle upgrade on first open, which is fine, take it.
- `core/` — a pure Kotlin/JVM module (`kotlin("jvm")`, no Android dependency on purpose): `Quote`, `QuoteCorpus` (parses JSON via `org.json`), and `QuoteSelector` (random no-repeat-until-exhausted), each with JUnit tests. Because it has no Android dependency, **this module can be built and tested with just a JDK and Gradle — no Android SDK, no emulator, no Android Studio required.** That's the fastest way to verify the actual logic.
- `app/` — the Android application module: `MainActivity` (a placeholder Compose screen proving the corpus loads), and `widget/ColdOpenWidget.kt` (a Jetpack Glance `GlanceAppWidget` + `GlanceAppWidgetReceiver`), plus the manifest, widget provider XML, and a widget-picker preview layout.

## Unlike iOS: no separate widget process

An Android home-screen widget isn't a separate installable target the way an iOS WidgetKit extension is — it's a `BroadcastReceiver` (`ColdOpenWidgetReceiver`) plus Glance composable code living inside the same `:app` module and process. That's architecturally simpler in one specific way: persisting `QuoteSelector`'s "already shown" state across widget updates just needs `SharedPreferences`, not an App Group-style shared container — and that's now actually wired up (see `ColdOpenWidget.loadRandomQuote`), not just noted as possible.

## Deliberately missing: the Gradle wrapper

There's no `gradlew` / `gradlew.bat` / `gradle/wrapper/gradle-wrapper.jar` here. The wrapper `.jar` is a binary bootstrapper generated by an actual Gradle install — fabricating one by hand isn't safe or meaningful. Two real options once you're on a machine with the toolchain:

1. Open this `android/` folder in Android Studio — it detects the missing wrapper and offers to generate it.
2. Or, with Gradle installed locally: `cd android && gradle wrapper --gradle-version 8.10` (or current stable), which generates the wrapper properly.

## Verify the logic first, then the app

```bash
cd android
gradle :core:test
```

(or `./gradlew :core:test` once the wrapper exists). This runs `QuoteSelectorTest` and `QuoteCorpusTest` without touching the Android SDK at all. If this fails, nothing built on top of it will work either.

The bundled corpus asset (`app/src/main/assets/quotes.json`) is kept in sync automatically now: `app/build.gradle.kts` registers a `syncCorpus` task (runs `npm run sync:android` from the repo root) and hooks it into `preBuild`, so it re-copies `corpus/quotes.json` before every build rather than relying on someone remembering the manual step. You can still run it by hand if you just want the asset current without a full build:

```bash
npm run sync:android
```

(from the repo root). **The `preBuild` wiring itself is unverified** — it's a standard Gradle idiom (a custom `Exec` task depended on by `preBuild`), but there's no Gradle here to confirm it actually fires, or that `npm` is reliably on `PATH` when Android Studio invokes Gradle rather than a plain shell. If it doesn't fire, `npm run sync:android` by hand is the fallback.

Then, in Android Studio: run the `app` configuration on an emulator or device, and separately add the "Cold Open" widget to a home screen to check it renders.

## Known gaps (see TASKS.md for the tracked version of this list)

- **Not yet built, synced, or run anywhere.** First real task on a machine with the Android toolchain: does this even compile? The `androidx.glance.*` API calls in `ColdOpenWidget.kt` were written from training knowledge and pinned-version docs, **not verified against the actual Glance 1.1.1 API surface** — expect to fix import/signature drift on first build.
- **No Gradle wrapper checked in** (see above) — generate it locally rather than trusting a hand-written one.
- **The `syncCorpus` → `preBuild` wiring is unverified** — see above.
- **No-repeat selection is now wired into the widget, with persistence.** `ColdOpenWidget.loadRandomQuote` uses `:core`'s `QuoteSelector`, reading/writing the "already shown" set via `SharedPreferences` around each draw. `QuoteSelector` gained an `alreadyShown` constructor param and a `shownTexts` property to support this, plus 4 new unit tests — all still unverified by an actual compiler/test run (no Kotlin toolchain here), traced by hand instead.
- **Manual-refresh action is wired but unverified.** `RefreshAction : ActionCallback` (in `ColdOpenWidget.kt`) calls `ColdOpenWidget().update(context, glanceId)`, triggered by a clickable "New quote" `Text` (`GlanceModifier.clickable(onClick = actionRunCallback<RefreshAction>())`) laid out in a `Row` next to the attribution text. API shape confirmed against the official [Glance user-interaction doc](https://developer.android.com/jetpack/compose/glance/user-interaction), not just training knowledge — but still not compiled against the real Glance 1.1.1 surface.
- **Share flow is wired but unverified.** The widget's new "Share" tap uses Glance's `actionStartActivity<ShareActivity>()` to launch `ShareActivity` (invisible/no-history, `Theme.ColdOpen.Invisible`), which renders the card, writes it via a newly-registered `FileProvider` (`file_paths.xml`, scoped to just the `share_cards/` cache subdirectory), and fires `ACTION_SEND` through `Intent.createChooser` before finishing. The `actionStartActivity`/`ActionParameters` shape was checked against the official Glance doc (confirmed `ActionParameters.Key` has no public `.name` — that's why `ShareIntentKeys` exists as plain shared string constants instead), but none of it has been compiled.
- **Scheduled auto-refresh is wired but unverified.** `cold_open_widget_info.xml`'s `updatePeriodMillis` is now `14400000` (4 hours) instead of `0` — the platform's own periodic-update mechanism, not WorkManager (see the code comment for why). No Gradle/Android SDK here to confirm `GlanceAppWidgetReceiver` actually re-renders on each fire, and this mechanism is documented as "unreliable across OEMs" even when it does — that's an accepted tradeoff for a quote widget, not a bug to chase.
- **Large widget size added, no faction emblem yet.** `ColdOpenWidget` now declares `sizeMode = SizeMode.Responsive(setOf(SmallSize, MediumSize, LargeSize))` (checked against the official Glance build-ui doc), and `ColdOpenWidgetContent` reads `LocalSize.current` to scale font sizes/padding up for the large bucket. `cold_open_widget_info.xml`'s `maxResizeWidth`/`maxResizeHeight` widened to 360×360dp so that bucket is actually reachable. The faction emblem CLAUDE.md's design direction calls for at this size is deliberately not implemented — same reasons as iOS (design decision + missing quote-to-faction mapping), logged in TASKS.md.
- **Instagram Stories direct-share is implemented but inert.** `InstagramStorySharing.kt` fires the documented `com.instagram.share.ADD_TO_STORY` intent action with the card's `content://` URI — but Instagram requires a registered Facebook App ID (as `source_application`) and rejects the share without one, per Meta's own docs. `FACEBOOK_APP_ID` is a deliberate blank placeholder; until it's filled in with a real ID (the same one covers both platforms), `isAvailable` stays `false` and `ShareActivity` falls back to the generic `ACTION_SEND` share sheet above.
- **App icon done.** Implemented as adaptive-icon vector drawables (`res/drawable/ic_launcher_background.xml` + an empty foreground layer, wired via `res/mipmap-anydpi-v26/ic_launcher.xml`) reproducing the "Cold Open Wipe + Starfield" concept as flat paths, including the three star flecks as circle paths — no PNG needed since `minSdk 26` already requires adaptive icon support. `AndroidManifest.xml` now sets `android:icon`/`android:roundIcon`. Not yet confirmed inside Android Studio.
- **No ktlint yet** — tracked as a follow-on once this project is confirmed to actually build (see root TASKS.md "Tooling & Quality Gates").
